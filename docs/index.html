Trade on EasyTrader from .NET

MofidEasySdk adds, edits and deletes orders on d.easytrader.ir. It takes care of request formats, the bearer token and error handling, so your code only deals with orders.

.NET 10 Async Thread-safe Dependency injection ready
Try the demo Read the docs View on GitHub
Three callsAddOrderAsync, EditOrderAsync and DeleteOrderAsync.
Typed rejectionsEvery OMS error maps to an OmsErrorKind you can switch on.
Safe timeoutsA timed-out request is reported as unknown state, never as a plain failure.
Token checksAn expired JWT is caught before sending, with a clear message.

Try it: interactive demo

Want to see the SDK work before writing code? The repository includes a small web app. Paste your token, fill in an order, and add, edit or delete it with a click.

Run it on GitHub

No install needed. GitHub Codespaces starts the demo in the cloud and opens it in your browser.

  1. Click the button and choose Create codespace. The first start takes a few minutes.
  2. The demo starts by itself and opens in a new tab. If it doesn't, open the Ports tab and click the globe icon next to EasyTrader demo.
  3. When you're done, stop the codespace so it doesn't use up your free hours.

The forwarded port is private: only you can open it, after signing in to GitHub.

Or run it on your machine

Terminal
git clone https://github.com/alireza267/MofidEasySdk.git
cd MofidEasySdk
dotnet run --project samples/MofidEasySdk.WebDemo

Your browser opens http://localhost:5080.

Using the demo

  1. Paste your token (see Get your access token). The page shows when it expires.
  2. Fill in the order: ISIN, buy or sell, price and quantity, then click Place order.
  3. Manage it in the order list: Edit changes price or quantity, and the row updates to the new order ID. Delete cancels it.

Every response appears in the activity log, including OMS rejections with their Persian messages and unknown state warnings after timeouts.

The orders are real. Test with small quantities and prices far from the market. Only you can open your demo, whether it runs in your codespace or on your machine, and the token is kept in memory only.

Why not run it right here on this page? The EasyTrader API only accepts browser requests from d.easytrader.ir, so the demo calls it from a .NET app instead.

Get your access token

The SDK uses the same token your browser uses. You pass it to the library yourself.

  1. Log in to d.easytrader.ir.
  2. Open DevTools (F12) → Network, and click any request to api-mts.orbis.easytrader.ir.
  3. Copy the value of the Authorization header. With or without the Bearer  prefix is fine.

Treat the token like a password. It can place orders on your account. Keep it out of source control and logs.

The token is a JWT and expires. The SDK reads its exp claim. Once it has expired, the SDK throws EasyTraderAuthenticationException without sending anything. Copy a fresh token when that happens.

Quick start

Create one client and reuse it. It's thread-safe and doesn't need disposing.

C#
using MofidEasySdk;

var client = new EasyTraderClient(token);

// Add a buy order: 244 shares at 20,520 Rials
OrderResponse added = await client.AddOrderAsync(new AddOrderRequest(
    SymbolIsin: "IRO1TBAN0001",
    Side: OrderSide.Buy,
    Price: 20520,
    Quantity: 244));

Console.WriteLine($"Order placed: {added.Id}");

// Edit it: the edit creates a NEW order with a NEW ID
OrderResponse edited = await client.EditOrderAsync(new EditOrderRequest(
    OrderId: added.Id,
    SymbolIsin: "IRO1TBAN0001",
    Price: 20520,
    Quantity: 270));

// Delete it: use the ID returned by the edit
await client.DeleteOrderAsync(edited.Id);

Each method returns an OrderResponse with the order's Id and the server's Message. A returned response always means the request was accepted, and Id is always set. Every other outcome throws an exception.

Edits create a new order. Once an edit is booked, the old order is no longer in the matching engine. Always use edited.Id for the next edit or delete.

Orders are valid for the trading day (OrderValidity.Day). Other validity types aren't supported yet.

Handling rejected orders

The OMS may create an order, assign it an ID, and then reject it. The server still answers HTTP 200, but with isSuccessful: false. The SDK turns that into EasyTraderOrderException:

C#
try
{
    await client.AddOrderAsync(request);
}
catch (EasyTraderOrderException ex)
{
    // ex.OrderId: ID of the rejected order (it isn't live), or null
    // ex.Error:   why it was rejected
    switch (ex.Error?.Kind)
    {
        case OmsErrorKind.MoneyBalanceIsNotEnough:
            Console.WriteLine("Not enough money in the account.");
            break;
        case OmsErrorKind.PriceIsNotInRange:
            Console.WriteLine("Price is outside the allowed range.");
            break;
        case OmsErrorKind.UserMoneyIsNotReady:
            Console.WriteLine("Balance isn't ready yet. Try again shortly.");
            break;
        default:
            Console.WriteLine($"{ex.Error?.Name} ({ex.Error?.Code}): {ex.Error?.Message}");
            break;
    }
}

OmsError has Kind, the server's Name (for example PriceIsNotInRangeError), its Persian Message, and its Code. Names this SDK version doesn't know yet come back as OmsErrorKind.Unknown, with Name still set.

BuyNotAllowedInThisSymbol / SellNotAllowedInThisSymbolBuying / selling not allowed on this symbol

Timeouts: unknown order state

Sometimes no response arrives within Timeout (30 s by default), or the connection breaks after the request was sent. The server may or may not have applied the request, so the SDK throws EasyTraderOrderStateUnknownException.

Don't blindly retry. A retried add can place a duplicate order. Check your orders on d.easytrader.ir first.

C#
try
{
    await client.AddOrderAsync(request);
}
catch (EasyTraderOrderStateUnknownException ex)
{
    // ex.Operation:     Add, Edit or Delete
    // ex.TargetOrderId: the order an edit or delete targeted (null for Add)
    logger.LogWarning("Order state unknown after {Operation} of {OrderId}; check before retrying",
        ex.Operation, ex.TargetOrderId);
}
catch (EasyTraderConnectionException)
{
    // Couldn't connect at all (DNS, TCP or TLS). Nothing was sent, so a retry is safe.
}

Replacing an expired token

Keep a StaticTokenProvider and give it a new token. There's no need to recreate the client.

C#
var tokens = new StaticTokenProvider(token);
var client = new EasyTraderClient(tokens);

Console.WriteLine($"Token expires at {tokens.ExpiresAt}");

// Later, when it expires:
tokens.SetToken(newToken);

To load the token from your own source, such as a secret store, implement IEasyTraderTokenProvider. It's called before every request.

Dependency injection

Program.cs
builder.Services.AddEasyTraderClient(options =>
{
    options.AccessToken = token;
});

// Inject IEasyTraderClient anywhere:
public class OrderService(IEasyTraderClient easyTrader)
{
    public Task<OrderResponse> BuyAsync(string isin, long price, long quantity) =>
        easyTrader.AddOrderAsync(new AddOrderRequest(isin, OrderSide.Buy, price, quantity));
}

// Swap the token at runtime:
app.Services.GetRequiredService<StaticTokenProvider>().SetToken(newToken);

AddEasyTraderClient returns an IHttpClientBuilder for adding your own handlers. Don't add automatic retries to add or edit calls: if a request times out after the server accepted it, a retry can place a duplicate order.
